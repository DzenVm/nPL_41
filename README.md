# Strategia archipelagu — SSR-сайт на Next.js 16

Лендинг під Google Ads для браузерної однокористувацької стратегії (гео Польща,
мова — польська). Технічний опис нижче — українською, весь контент самого
сайту — польською.

## Стек

- **Next.js 16 (App Router, Turbopack)** + **React 19** + **TypeScript**, справжній SSR
  (`export const dynamic = "force-dynamic"` на головній — сторінка рахує блок
  «сьогоднішніх умов» детерміновано на кожен запит, на сервері, а не білдиться
  один раз).
- Верстка — власна дизайн-система на **CSS Modules** з CSS custom properties,
  `color-mix()`, `light-dark`-подібна підтримка теми через
  `prefers-color-scheme`, контейнерні одиниці для карток. Без Tailwind/shadcn
  і без жодного готового UI-кіта — це свідомий вибір, щоб сайт не був схожий
  на типовий шаблонний landing.
- **next/font/google** — пара шрифтів Newsreader (заголовки) + Public Sans
  (текст), нетипова для landing-сторінок комбінація.
- Метадані через файлові конвенції App Router: `robots.ts`, `sitemap.ts`,
  `icon.svg` / `favicon.ico` / `apple-icon.png`, JSON-LD (`schema.org/Game`)
  прямо в `layout.tsx`.
- Інтерактивний клієнтський острівець (`AllocationPanel`) — невеликий слайдер
  без жодного зовнішнього стейт-менеджера, просто `useState`.
- 6 зображень — це не стокові фото і не фото з генератора зображень, а власноруч
  намальовані SVG-діаграми (мапа архіпелагу, схема логістики, цикл сезонів,
  дерево розвитку, схема ваги ризику, поглядовий макет панелу). Лежать
  у `public/images/*.svg`.
- Фавікон — власний абстрактний знак (лінія маршруту з двома точками), не
  логотип і не бренд-марка: `src/app/icon.svg` → рендериться в
  `favicon.ico` / `apple-icon.png` через `sharp` (скрипт разовий, не входить
  у продакшн-залежності).

## Структура сторінок

- `/` — головна, максимально наповнена: hero, детальний опис механіки,
  живий блок «умов дня» + інтерактивний слайдер, 6 систем гри, логістика,
  сезони, 4 шляхи розвитку, баланс ризику, «для кого ця гра», «чого тут
  немає», міні-FAQ, фінальний CTA.
- `/jak-grac` — покроковий розбір першої години гри та ігрового циклу.
- `/faq` — розширений список питань, згрупований по темах.
- `/kontakt` — контактна адреса (прив'язана до домену, плейсхолдер до заміни).
- `/polityka-prywatnosci`, `/regulamin` — юридичні сторінки (потрібні для
  проходження модерації Google Ads: контакти, політика даних, правила
  користування).

## Свідомі обмеження контенту (за ТЗ)

- Жодних вигаданих чи реальних брендів, жодного логотипу — тільки абстрактний
  графічний знак у фавіконі.
- Жодної лексики, дотичної до азартних ігор — навіть у формі заперечення.
  Погодна механіка описана як детермінований алгоритм (сід = дата), а не як
  випадковість.
- Гра описана як **виключно одноосібна**: без PvP, без чату, без рейтингів —
  це і зменшує ризики модерації (немає UGC/спілкування між користувачами),
  і є частиною самої концепції гри.
- Немає жодних заглушок чи «типових хвостів» — окрім самого домену, який
  буде наданий пізніше.

## Домен

Замінник домену — `https://domena-do-podmiany.pl`, заданий у
`src/lib/site.ts` через змінну середовища:

```
NEXT_PUBLIC_SITE_URL=https://твій-домен.pl
```

Після того як домен буде відомий: додати цю змінну в Vercel
(Project Settings → Environment Variables) і зробити redeploy. Увесь код
(canonical, OpenGraph, sitemap, robots.txt) автоматично підхопить нову адресу
— хардкоду домену в коді немає.

## Локальний запуск

```
npm install
npm run dev
```

## Продакшн-білд

```
npm run build
npm run start
```

Перевірено: чистий білд, чистий `npm run lint`, усі маршрути віддають 200,
SSR-блок умов дня рахується на кожен запит.

## Деплой на Vercel

1. Запушити цей репозиторій/гілку у Vercel як новий проєкт (framework
   визначиться автоматично як Next.js завдяки `vercel.json`).
2. Після отримання домену — прив'язати його в Vercel і додати
   `NEXT_PUBLIC_SITE_URL` зі значенням `https://<домен>` в Environment
   Variables (Production), потім redeploy.
3. Секретів, API-ключів чи зовнішніх інтеграцій проєкт не використовує —
   деплой без додаткової конфігурації.
